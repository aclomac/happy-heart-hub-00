# ERPOVO Android Wrapper (Capacitor)

This folder is created by Capacitor after running `bun run cap:add:android`.
It wraps the published ERPOVO web app in a native Android shell.

## Identity

| Field | Value |
| --- | --- |
| App name | **ERPOVO** |
| Package / Application ID | **`com.chairking.erpovo`** |
| Default URL | `https://happy-heart-hub-00.lovable.app` (Cloud Mode) |
| Override URL | set `CAP_SERVER_URL` env before `bun run cap:sync` |

The wrapper only changes how the WebView loads the existing PWA. It does
**NOT** modify sales / stock / purchase / payment cloud sync, and Local
Mode keeps using IndexedDB inside the WebView — device-local, no cloud
calls introduced by the wrapper.

---

## 1. One-time setup (developer machine with JDK 17 + Android SDK)

```bash
# 1. Install JS deps
bun install

# 2. Build the web bundle (powers offline/cached assets when shipped bundled)
bun run build

# 3. Add the Android platform (creates ./android — only first time)
bun run cap:add:android

# 4. Install ERPOVO placeholder icons + splash into the native project
bash scripts/install-android-assets.sh

# 5. Sync web assets + Capacitor plugins into the Android project
bun run cap:sync
```

> The `android/` folder is generated by step 3 and is NOT committed to git
> until you decide to. Re-running `cap:add:android` is destructive — only
> do it on a fresh checkout. Steps 4 and 5 are safe to re-run any time.

---

## 2. Build the debug APK

```bash
bun run android:build:debug
# equivalent to:  cd android && ./gradlew assembleDebug
```

**APK output path:**

```
android/app/build/outputs/apk/debug/app-debug.apk
```

Debug APKs are auto-signed by the Android debug keystore. **No release
signing key is required** for sideload testing or internal QA.

---

## 3. Install on an Android phone

### Option A — USB cable (adb)

```bash
# Enable Developer Options + USB debugging on the phone, then:
adb devices                                   # confirm phone is listed
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

### Option B — Sideload the APK file

1. Copy `app-debug.apk` to the phone (USB, Google Drive, email, etc.).
2. On the phone, allow "Install unknown apps" for the file manager.
3. Open the APK file → tap **Install**.

The app icon will appear as **ERPOVO**.

## 4. Manual test checklist (debug APK)

Run through this list after each new APK:

- [ ] App icon shows "E" monogram on navy background; launches without crash
- [ ] Splash screen shows briefly, then the welcome / login flow renders
- [ ] **Cloud Mode** — log in, company list loads, dashboard renders
- [ ] **Local Mode** — toggle on, data stays on device, no network calls
- [ ] Open **Sync Center** — status tiles (Sales / Stock / Purchases / Payments) render
- [ ] Create a sale in Cloud Mode → appears under "Synced"
- [ ] Toggle airplane mode → create another sale → it shows "Pending"
  → re-enable network → queue drains, sale moves to "Synced"
- [ ] Hardware back button on root closes the app
- [ ] No white screen, no JS console errors (inspect via `chrome://inspect`)
- [ ] After a new web deploy, relaunching the app picks up the new build
      (NetworkFirst HTML/JS caching guarantees this — see `vite.config.ts`)

## 5. Cache safety (Android does not show stale JS)

`vite.config.ts` is configured so the WebView always fetches fresh code:

- **PWA service worker** uses `registerType: "autoUpdate"` plus
  `skipWaiting: true`, `clientsClaim: true`, and `cleanupOutdatedCaches: true`.
- HTML navigations and JS/CSS requests use **NetworkFirst** with a 3s
  network timeout, falling back to cache only when offline.
- Supabase, REST, RPC, auth, and storage requests are **NetworkOnly** —
  never cached.

Result: a freshly deployed Cloud-Mode build is picked up on the next
app launch with no manual cache clear.


This APK cannot be installed without signing. Use the signing flow below
before publishing.

## 7. Release signing (required for Play Store, NOT for debug/sideload)

1. Generate a keystore (one time, keep it safe — losing it locks you out
   of Play Store updates forever):
   ```bash
   keytool -genkey -v -keystore erpovo-release.keystore \
     -alias erpovo -keyalg RSA -keysize 2048 -validity 10000
   ```
2. Create `android/keystore.properties` (gitignored):
   ```
   storeFile=../erpovo-release.keystore
   storePassword=********
   keyAlias=erpovo
   keyPassword=********
   ```
3. Wire `signingConfigs` in `android/app/build.gradle` (`release { ... }`).
4. Build:
   ```bash
   cd android
   ./gradlew assembleRelease    # signed APK
   ./gradlew bundleRelease      # AAB for Play Store
   ```

## 9. What is NOT changed by the Android wrapper

- ❌ Sales / stock movement / purchase / payment cloud sync logic
- ❌ Local Mode (still device-local IndexedDB inside the WebView)
- ❌ Database migrations
- ❌ Idempotency keys / queue replay behavior
- ❌ Sync Center UI

The wrapper is a thin native shell around the existing web app.
